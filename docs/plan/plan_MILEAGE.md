# План: пробег не больше 400 000 км, иначе review

Сверка с `docs/setup/code_map.md` и со списком мест, где читается пробег (`docs/setup/agents.md`). Код в этом шаге не меняется.

Сейчас решение считает только LTV: `AssessmentService::assess()` вызывает `DecisionEngine::decide($ltv)` и не смотрит на пробег. Пробег уже есть в нормализованном input. Порог 400 000 в `rules.php` отсутствует. `vehicle.max_mileage_km` = 500000 — это отсечка валидации, не решение.

## Файлы

- `backend/config/rules.php` — добавить порог решения, например `vehicle.review_mileage_km` = 400000; `max_mileage_km` не менять.
- `backend/src/Domain/AssessmentService.php` — после `decide($ltv)`: если решение `approve` и пробег больше порога, заменить на `review`.
- `tests/Unit/AssessmentServiceTest.php` — случаи границы пробега при LTV, который иначе даёт `approve`.

`DecisionEngine::decide(float $ltv)` пробег не видит. Сигнатуру не расширять: пробег уже лежит в `$input['mileage']` после `ApplicationValidator::validate()`.

## Шаги

1. Положить число 400000 в `rules.php`, не в PHP-код решения.
2. В `AssessmentService::assess()` после строки с `decide($ltv)` ужесточить только `approve` до `review`, если пробег больше порога.
3. Не трогать `reject`: пробег не должен смягчать отказ по LTV, пока заказчик не скажет иначе.
4. `approved_limit` уже становится 0 для любого решения кроме `approve` — отдельная правка не нужна.
5. Добавить тесты границ в `AssessmentServiceTest`. `max_mileage_km` и валидатор не менять.

## Тесты

- 399999 — пробег не больше 400000, решение остаётся тем, что дал LTV.
- 400000 — ровно формулировка «не больше»; по тексту задачи это ещё не `review`.
- 400001 — при LTV-`approve` решение становится `review`, одобренный лимит 0.
- Пустой пробег — поля нет; валидатор подставляет -1 и бросает ошибку `mileage`, до решения дело не доходит.

Существующие фикстуры 84000 и 96000 остаются зелёными: оба не больше 400000.

## Риски

- `max_mileage_km` = 500000 по-прежнему пропускает 400001 к расчёту решения. Если этот порог опустить до 400000 или ниже, правило `review` перестанет срабатывать: заявка умрёт на валидации.
- Жёстко прописанные 400000 в PHP разойдутся с `rules.php`. Число только в конфиге.
- Причина `review` в ответ и в таблицу `decisions` не попадает: колонки reason нет.
- Не входит: форма, схема БД, `DecisionEngine`, `LtvCalculator`, `max_mileage_km`, лимит по возрасту (`ltv_by_age`).
